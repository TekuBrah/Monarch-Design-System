# Monarch Design System — Phase 0 Audit Report (2026-07-27)

Consolidates and triages the findings from Steps 0.1–0.6 (ground truth, API
surface, token discipline, CSS isolation, a11y, packaging). Findings are
taken verbatim from those steps' output — this report does not re-run any
grep or re-derive any claim. Where a call is ambiguous, it's marked "Needs
decision" rather than guessed.

**Triage buckets** are the three offered in the roadmap's own 0.7 definition:
fix in **Phase 1** (blocking API decisions), fix in **Phase 2** (packaging),
or **Park**. Items that don't cleanly fit any of the three — because whether
they're even a defect is itself unresolved — are marked **Needs decision**
rather than forced into one of the three.

## B. Already known, confirmed accurate

These match pre-existing parked roadmap items or previously-estimated figures — 0.1–0.6 didn't discover them fresh, they *quantified or reconfirmed* them:

- **#4 — Size-vocabulary count.** Previously estimated "7+ vocabularies"; now precisely counted at **9 across 14 components**. Same open item, more exact.
- **#5 — `disabled`/`isDisabled` split.** Previously known qualitatively as split; now precisely counted at **5 vs 11**.
- **#10 — Chips/Badge alias-color usage.** Matches the roadmap's own parked line item verbatim ("Stays as faithful Figma-source recording unless a deliberate design decision changes it") — 0.3 confirmed this is still accurate and found no *new* violation beyond it.
- **#19 — Tabs keyboard nav / `ButtonGroup role="group"`.** These were previously-landed fixes explicitly named in the roadmap's own 0.5 instruction ("confirm prior fixes landed") — 0.5 confirmed both, no regression.

## C. Newly surfaced, not previously tracked

Findings that 0.1–0.6 discovered fresh — no prior roadmap or handoff reference:

- **#6 — `onClick` signature split** (8 components leak `React.MouseEventHandler`, 5 use plain `() => void`).
- **#7 — `onSelect` optionality mismatch** between `MenuItem` and the `Navigation` family.
- **#12 — `Badge`'s `dark` appearance bypasses both the alias and mapped token layers**, using a raw `--brand-*` primitive directly.
- **#13 — `-press`/`-pressed` naming inconsistency** in the generated Mapped token set (error family vs. every other status family).
- **#17 — `AppShell.css`'s unscoped `html, body {}` rule** — the single most severe finding in the whole audit, contingent on Phase 2.1 actually separating it out.
- **#22 — `SelectWalletAccount`'s complete absence of focus-indication CSS**, the one outlier in an otherwise-consistent component family.
- **#21 — Escape-to-close gap** across `Select`/`SelectTransfer`/`SelectWalletAccount`/`TimePicker`/`Menu`.
- **#18 — `.stf`/`.swa` naming outliers** vs. every other component's descriptive class name.
- **#23 — `Tabs` missing Home/End** key support.

## D. Items needing a decision before triage (4)

These can't be filed into Phase 1 / Phase 2 / Park because whether they're even a defect is unresolved:

1. **#2 — Tab/ToastMobile showcase-anchor structure.** Intentional combined-section design, or a gap to fix?
2. **#8 — `variant` vs `appearance` split.** Plausibly a deliberate semantic distinction (structural type vs. surface style) — 0.2 explicitly did not confirm it as a defect. Needs a call on whether the distinction is real and should be documented as a rule, or whether it should collapse to one name.
3. **#18 — `.stf`/`.swa` naming.** 0.4 calls these "unexplained" outliers, not a confirmed-wrong pattern — rename to descriptive names (matching every other component) vs. leave as deliberate abbreviations is a judgment call, not a mechanical fix.
4. **#24 — `isRequired` coverage gap** (`Select`, `DatePicker`, `TimePicker`, `TextArea`, `SelectTransfer`, `SelectWalletAccount` have no `isRequired` prop). Cannot be resolved without Figma access, which this read-only local sweep did not have — unknown whether the source genuinely has no "required" variant for these, or whether it's an oversight.
